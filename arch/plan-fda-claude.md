## 0. Итог подхода

Детект — **только на стороне агента** (он единственный честный свидетель своего TCC-доступа;
приложение имеет ДРУГУЮ TCC-идентичность, его проба — ложный сигнал). Проба = `os.listdir(WATCH_DIR)`
через уже используемый python3, маппинг errno → тристейт `ok|denied|missing`; результат + timestamp
пишутся в `state.json` (аддитивно, в блок `agent`, тем же атомарным RMW-паттерном, что `batch_state`).
UI — **новый компонент `FolderAccessCard`** по грамматике EngineSetupCard (те же 4 подачи:
блокер/баннер/шаг Setup/строка Настроек, гибрид D37 по hasRawHistory), приоритетом НИЖЕ движкового
онбординга. «Проверить снова» = `launchctl kickstart` (без `-k`) + ожидание свежего probe-timestamp
в state.json (событийно, через уже существующий stateWatcher). Кнопка карточки открывает панель FDA
(существующий `openFullDiskAccess`) и кладёт путь раннера в буфер. Замыкание CJM: агент на
**переходе → denied** сам поднимает приложение (`open -b`, паттерн new-batch) — пользователь узнаёт
о проблеме, даже если никогда не открывал окно.

## 1. Решения по семи арх-вопросам

### В1. Детект в bash: как отличить TCC-отказ от пустой папки

**Решение:** python-проба `os.listdir(WATCH_DIR)` (не `ls`/glob и не probe-файл):

| Результат пробы | Состояние | Обоснование |
|---|---|---|
| listdir успешен (пусто или нет) | `ok` | честно пустая папка = `ok` + 0 файлов |
| `PermissionError` (EPERM **или** EACCES) | `denied` | TCC даёт EPERM; классический chmod — EACCES; для пользователя оба = «нет доступа», а слияние делает chmod-симуляцию в тестах валидной (В6) |
| ENOENT / ENOTDIR | `missing` | папка удалена/переименована/том отключён — ЧЕСТНО другое состояние, лечится не FDA |
| прочие OSError | `missing` + errno в лог | ремедиация FDA не подходит; молчим в UI, шумим в логе |

- **Почему python, не bash:** `[[ -d ]]`/`ls` не различают ENOENT и EPERM без парсинга stderr-строк;
  python даёт точный errno; python3 уже обязателен для всех state-писателей (нет python — нет и
  записи state.json, отдельная bash-ветка детекта бессмысленна → как у всех писателей: guard и no-op).
- **Почему не probe-файл (touch):** пишет мусор в папку пользователя; read-only listdir достаточен.
- **Где в жизненном цикле:** каждый run, после захвата lock и **до** проверки `ebook-convert`
  (строки ~1259–1261 watcher.sh). Стоимость ~10–20 мс (один короткий python). Проба после
  top-level `mkdir -p "$WATCH_DIR"` (стр. ~99, тот же процесс) — честно-отсутствующая папка
  при наличии доступа успевает самовосстановиться, проба видит уже излеченное состояние.
  До engine-check — чтобы флаг оставался свежим даже при отсутствующем движке (ранний exit 1
  не оставляет стейл-окна); приоритет подач при этом решает UI (В3), не порядок в скрипте.
- **False-positive-матрица:** удалённая папка при живом доступе → mkdir -p её воссоздал → `ok`
  (самолечение, как сегодня). Том отключён → mkdir падает, listdir ENOENT → `missing` (не карточка
  FDA). chmod 000 → `denied` (карточка FDA формально «не тот» ремедий, но кейс экзотический,
  «Проверить снова» продолжит честно показывать denied; принято осознанно).
- **Замыкание CJM (транзитивный pop):** если предыдущее значение в state.json ≠ `denied`, а проба
  дала `denied` → однократный best-effort `( open -b com.arrivarus.fb2toepub & )` — ровно паттерн
  new-batch-pop (стр. ~1460). Edge-семантика по сравнению prev/next: повторные fires при том же
  denied НЕ дёргают окно; закрыл окно — не пристаём. На `denied → ok` popа нет (успех и так виден).
  Опора на боевой факт: WatchPaths будит агента даже без FDA (лог 2026-07-22).

### В2. Контракт state.json (D13)

Аддитивно, внутрь существующего блока `agent` (schema остаётся 1 — эволюция как у `batch`):

```json
"agent": {
  "watch_dir": "/Users/x/Desktop/fb2-to-epub",
  "folder_access":    "ok" | "denied" | "missing",   // NEW; отсутствует у старого агента
  "folder_access_ts": "2026-07-22T09:31:04Z"          // NEW; ISO-8601 Z, время последней пробы
}
```

- **Писатель:** новая функция `folder_access_state()` в watcher.sh — тот же атомарный
  read-modify-write через python (tmp → fsync → os.replace), меняет ТОЛЬКО эти два ключа,
  сохраняет всех соседей (как `batch_state`). Пишет **на каждом прогоне** (не только по изменению):
  `folder_access_ts` — это доказательство свежей проверки, на нём держится обратная связь
  «Проверить снова» (В4). Одна лишняя атомарная запись на fire — копейки (агент событийный).
- **Кто сбрасывает:** только сам агент следующей пробой (`denied → ok` после выдачи гранта;
  TCC-грант применяется к НОВЫМ процессам, а агент короткоживущий — каждый fire новый процесс,
  перелогин не нужен). Приложение не пишет никогда (D13).
- **Обратная совместимость:** старое приложение + новый агент — лишние ключи игнорируются Codable;
  новое приложение + старый агент — поля отсутствуют → decode в `nil` → **никаких подач**
  (поведение сегодняшнего дня). Неизвестная строка в `folder_access` (будущий агент) → `nil`
  (forward-compat). `state.json` живёт в `~/Library/Application Support` — вне TCC-зон, агент
  может писать его ВСЕГДА (подтверждено боевым логом: лог в `~/Library/Logs` писался при отказе).

### В3. Подачи UI: состав и приоритет

**Новый компонент `FolderAccessCard`** (app/FolderAccessCard.swift), НЕ расширение
EngineSetupCard.Phase: у FDA свой крошечный автомат (denied / checking / stillDenied / timeout) и
свои действия; смешивание раздуло бы матрицу «4 подачи × N фаз» чужого, только что отгруженного
(v1.0.0) компонента. Визуальная грамматика и токены — те же (Tokens C/M/F/CO, warn-стили баннера,
скелет блокера/step-row/settings-row повторяем по образцу, без рефакторинга EngineSetupCard).

Подачи (зеркало движковых, D46 «полный паттерн по образцу движка»):

| Подача | Когда | Что |
|---|---|---|
| **Блокер** (Status) | `denied` и НЕТ raw-истории | замена контента: иконка, «Нет доступа к папке», объяснение, шаги 1-2-3, CTA «Открыть настройки и скопировать путь», «Проверить снова» |
| **Баннер** (Status) | `denied` и ЕСТЬ raw-история | warn-карточка под хедером, контент виден и приглушён (ring mute — как movок-баннер: конвертация одинаково невозможна); те же шаги компактно + 2 кнопки |
| **Шаг Setup** | `denied` на момент построения Setup | ряд «ДОСТУП К ПАПКЕ» **сразу после ДВИЖКА** (порядок задан D46), amber; кнопка — handoff на Status (паттерн CAL-4 setup-handoff: Setup display-only, живой флоу на Status) |
| **Строка Настроек** | всегда есть (существующая) | при `denied` — warn-подстрока «нет доступа к папке — конвертация стоит», действие = комбо открыть+скопировать; при `ok`/отсутствии поля — **байт-в-байт сегодняшний пассивный вид** (гарантия миграции В7) |

- **Шаг Setup показывается только при явном `denied`:** на свежей машине Setup строится ДО первой
  пробы (поле отсутствует) — рисовать зелёное «доступ есть» было бы враньём; при отсутствии поля
  визард остаётся двухшаговым, как сегодня. D46-требование «шаг сразу после движка» выполняется
  ровно в проблемном состоянии.
- **Приоритет против движка (роутер контента Status):** `effectivePhase` движка (форс → живой
  инсталл → отсутствие движка) **сначала**; FDA-карточка — только при `enginePhase == nil &&
  folder_access == .denied`. Логика CJM: движок → доступ. Нет движка И нет доступа → показываем
  движок; после установки движка installer сам делает kickstart → проба → флаг ложится →
  FDA-карточка всплывает следующим кадром. Стейл-`denied` при отсутствующем движке невидим по
  построению (гейт на enginePhase).
- **Тексты (ты-форма, голос приложения; финал — на ревью текстов):**
  блокер: «Нет доступа к папке» / «macOS закрывает Desktop, Документы и Загрузки от фоновых
  программ. Разреши доступ один раз — и конвертация заработает.» / шаги: «1. Нажми „+" в списке ·
  2. Cmd-Shift-G и вставь путь — он уже в буфере · 3. Включи переключатель у fb2-to-epub-runner.sh» /
  CTA «Открыть настройки и скопировать путь» / secondary «Проверить снова»; фидбек: «Доступа пока
  нет — проверь шаги и попробуй ещё раз» / таймаут: «Агент не ответил. Проверь, что агент активен».
- Высота окна меняется (баннер добавляет, блокер укорачивает) — существующий refitWindowHeight;
  проверка на МАКСИМУМЕ контента (урок native-window-cap-height).

### В4. «Проверить снова»: механика и латентность

**kickstart, не touch-файл:** у приложения может НЕ быть своего доступа к Desktop — «touch папки»
недоступен по построению; бросать мусор в covers/jobs — хак. `launchctl kickstart` (новый
3-строчный `EngineClient.kickstartGentle()`, **без `-k`**: `-k` убивает живой прогон; хотя при
denied батчей не бывает, безопасность по построению дешевле рассуждений). rc ≠ 0 → сразу ветка
«Агент не ответил».

**Обратная связь — по `folder_access_ts`, событийно:**
1. нажатие → запомнили `pressedAt`, состояние `checking` (кнопка disabled + спиннер), kickstart;
2. агент прогнался → всегда переписал `folder_access(+_ts)` → stateWatcher приложения (DispatchSource
   на каталоге state/, debounce 150 мс) → refreshStatusNow;
3. приложение сравнивает: `folder_access_ts > pressedAt` и — `ok` → карточка растворяется
   (роутер сам перестал её показывать; это и есть success-фидбек), `denied` → `stillDenied`
   («Доступа пока нет…», кнопка снова активна);
4. таймер 8 с без свежего ts (агент выключен / python сломан / launchd молчит) → `timeout`-строка.

Латентность: kickstart → процесс → проба+запись ≤1 с → debounce 150 мс → UI ≈ **1–2 с**
(ThrottleInterval=5 kickstart'ом обходится; худший случай всё равно < 8 с таймаута).
Транзиентные состояния (`checking/stillDenied/timeout`) живут ТОЛЬКО в приложении (хост мутирует
StatusStore, как весь существующий стейт) — агент пишет факты, приложение владеет интеракцией.

### В5. Клипборд: откуда путь раннера

**Источник правды — plist:** `ProgramArguments[0]` через plutil (образец — существующий
`readWatchDir`), новый `EngineClient.runnerPath()`. Фолбэк (plist нечитаем) — канонический
`<home>/Library/Application Support/fb2-to-epub/bin/fb2-to-epub-runner.sh` через `EngineHome.resolve()`
(НЕ литеральная `~`). В буфер — **абсолютный** развёрнутый путь (Cmd-Shift-G его ест безусловно);
на карточке показываем тильда-свёрнутый. Копирование — **по нажатию CTA** (не при появлении
карточки: чужой клипборд без явного намерения не трогаем; повторное нажатие — снова копирует).

### В6. Тестируемость без настоящего TCC

- **EPERM vs EACCES — непринципиально by design** (В1): проба сливает их в `denied`, поэтому
  `chmod 000` в харнессе даёт ровно ту же ветку, что боевой TCC. Это осознанная плата за
  тестируемость, зафиксирована в контракте пробы.
- **Bash-тесты** `tests/run-folder-access-tests.sh` — паттерн run-sticky-batch-test.sh: функции
  `probe_watch_dir_access` / `folder_access_state` извлекаются ВЕРБАТИМ из shipping-watcher
  (якорь `^fn() {` … `}`), гоняются в песочнице против throwaway STATE_FILE/WATCH_DIR.
  Кейсы: ok-пустая · ok-с-файлами · denied (chmod 000, с возвратом прав в trap) · missing
  (WATCH_DIR под обычным файлом → ENOTDIR) · сохранение соседей state.json при RMW ·
  монотонность ts на двух прогонах · PYTHON3=/nonexistent → no-op без падения · edge-pop:
  переход prev≠denied→denied триггерит open-ветку ровно один раз (проверка по логу, `open`
  подменён стабом в PATH). Плюс smoke полного watcher: изолированные FB2_STATE_DIR/LOG/WATCH_DIR
  (env-каналы уже существуют), EBOOK_CONVERT=/bin/echo, chmod-denied папка → state.json несёт
  `denied`, run завершился чисто.
- **Прод-страж (урок 015/018):** снапшот mtime/size реальных `~/Library/.../state/state.json`,
  лога и `~/Library/LaunchAgents/*.plist` ДО сьюты, сверка ПОСЛЕ — расхождение = красный тест.
  Никаких launchctl/бутстрапов в тестах вообще (детект-тесты в них не нуждаются — латч не задействуем).
- **Swift-юниты** (app-слой): decode-матрица (`absent/ok/denied/missing/мусор` → enum/nil) ·
  приоритет роутера (enginePhase бьёт FDA; hasRawHistory ветвит блокер/баннер) · автомат
  recheck с инжектированными часами (checking→stillDenied/timeout) · runnerPath (plist → фолбэк) ·
  парсер FB2_FORCE_FOLDER_ACCESS.
- **Display-only оверрайд** `FB2_FORCE_FOLDER_ACCESS = denied | denied-checking | denied-timeout | ok`
  — зеркало FB2_FORCE_INSTALL_STATE: без защёлки (Инвариант 6 разрешает display-only), на диск не
  пишет, кнопки под форсом — no-op через существующую обёртку `onboardingAction`. Даёт скриншоты
  всех подач для дизайн-ревью без настоящего TCC.
- **Живой e2e (урок 016) — боевой Мак человека, он УЖЕ в состоянии denied:** карточка видна →
  CTA открывает панель, в буфере верный путь → грант по шагам → «Проверить снова» → карточка ушла →
  реальный .fb2 сконвертирован. Плюс негатив: на Маке С грантом после обновления — ноль визуальных
  отличий (скриншот-сверка Status/Настройки до/после).

### В7. Миграция: у старых пользователей с грантом ничего не мигает

Тройная гарантия: (1) любая подача требует **явного** `folder_access == "denied"` — отсутствие поля
(старый агент, стейл state.json) и `ok` рендерятся байт-в-байт как сегодня; (2) у пользователя с
грантом первая же проба нового агента пишет `ok` — состояние «denied» недостижимо; (3) строка
Настроек при ok/absent не меняется вовсе, шаг Setup не появляется, роутер Status не трогается.
`runner.sh` не меняется ни байтом (FDA-грант по байтам, installer и так копирует его только по
`cmp -s`-отличию); plist не меняется (новых env не нужно); schema=1. Единственное новое поведение —
у тех, у кого КОНВЕРТАЦИЯ УЖЕ МОЛЧА СЛОМАНА: они впервые об этом узнают. Это и есть фича.

## 3. Порядок сборки (майлстоуны по зависимостям)

1. **FDA-1 — агент: детект + контракт** (фундамент, всё остальное читает его выход):
   проба + писатель + размещение в run-цикле + edge-pop; bash-тесты + прод-страж.
   **Валидация R1 первым шагом:** до любого UI-кода прогнать на боевом denied-Маке kickstart и
   предъявить `state.json` c `"folder_access":"denied"` (validation-first; если гипотеза errno
   не подтвердится — переделываем пробу, UI не пострадал).
2. **FDA-2 — UI display-only** (зеркало этапа CAL-2; после заморозки контракта FDA-1 может идти
   параллельно хвосту его тестов — файлы не пересекаются): decode в StateModel, FolderAccessCard
   (4 подачи, тексты), FB2_FORCE_FOLDER_ACCESS, инертные кнопки; скриншоты всех подач.
3. **FDA-3 — сшивка + тесты + релиз**: kickstartGentle/runnerPath, recheck-флоу с таймером,
   клипборд+openFDA комбо, живая проводка Setup/Настроек, Swift-юниты, живой e2e на боевом Маке,
   README §FDA (абзац «приложение само покажет карточку и скопирует путь», ручной путь остаётся
   фолбэком), версия 1.0.1. ⛔ СТОП-точка релиза (демо человеку → явное «выкладывай»).

| **R1 (главный):** допущение «python-listdir под launchd без FDA даёт PermissionError» | подтверждено косвенно боевым логом (скан «пустой»), но проверяется ЯВНО первым шагом FDA-1 на боевом Маке — до постройки UI |
| R2: kickstart не срабатывает (агент не бутстрапнут / выключен) | rc-ветка → «Агент не ответил»; статус агента и так виден бейджем |
| R3: панель FDA на macOS 11–12 открывается «крупнее» (Security-панель без якоря) | ссылка та же, шаги валидны; openFullDiskAccess уже отгружен в Настройках без жалоб |
| R4: раннер УЖЕ в списке FDA, но выключен (частичный грант) | шаг 3 текста — «включи переключатель», покрывает обе ветви (добавить/включить) |
| R5: пользователь перезаписал буфер между CTA и вставкой | текст шага «путь уже в буфере», CTA повторно копирует; приемлемо |
| R6: launchd не fire'ит WatchPaths без FDA на какой-то версии macOS | боевой факт говорит «fire'ит»; страховка — RunAtLoad (логин) и kickstart из «Проверить снова» дают ещё два канала пробы |
| R7: «missing» без UI смутит пользователя с отключённым томом | сознательный скоуп v1.0.1 (D46 = FDA); контракт уже тристейт — UI для missing добавится без изменения агента |

Отвергнутые альтернативы: детект в приложении (чужая TCC-идентичность — ложный сигнал);
расширение EngineSetupCard.Phase (связывание автоматов, риск регресса v1.0.0); probe-файл
(мусор в папке пользователя); `kickstart -k` (убивает живой прогон); запись флага только по
изменению (ломает обратную связь «Проверить снова»); чтение TCC.db для верификации гранта
(хрупко; допустимо только как ручной диагностический приём, не в продукте).
