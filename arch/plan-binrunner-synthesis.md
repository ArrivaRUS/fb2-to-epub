## Единогласно (оба плана)
- **Вариант A:** standalone immutable Mach-O helper в `~/Library/Application Support/fb2-to-epub/bin/`,
  ProgramArguments[0] → он; plist/launchctl-контракт сохраняется.
- **B отклонён:** ad-hoc DR = cdhash главного бинаря; helper-в-бандле не матчится, а каждый
  авто-апдейт молча убивал бы грант. **C отклонён:** SMAppService не даёт стабильной identity
  без Developer ID; рефакторинг без решения. Трек «после Developer ID».
- **spawn+wait, НЕ exec** (load-bearing): exec заменил бы Mach-O-образ на /bin/bash и вернул баг;
  helper остаётся живым responsible-родителем, дети (bash→python3→Calibre) атрибутируются к нему.
- **Golden artifact:** собран и заморожен ОДИН РАЗ, хранится в git байт-в-байт (+исходник,
  +PROVENANCE: SHA-256, cdhash, окружение сборки). Пересборка = смена cdhash = молчаливая смерть
  гранта у всех — воспроизводимая сборка только для аудита, НЕ источник релиз-файла.
- Миграция существующих установок: старый грант не переносим (subject был /bin/bash) — один
  новый грант неизбежен; карточка v1.0.1 ведёт к нему без изменений механики.

## Решения судьи по расхождениям
1. **Имя: `fb2-to-epub-agent`** (#1). В FDA-панели человека уже висит мёртвый включённый
   `fb2-to-epub-runner.sh` — почти одинаковое имя (Sol сохранял «runner») спровоцирует «уже сделано».
2. **Старый runner.sh ОСТАВИТЬ один релиз** (Sol) — дешёвый rollback-путь; удалить в v1.0.3+.
   (#1 предлагал удалить сразу — отклонено.)
3. **Порядок миграции (Sol, критично):** plist перепекается на новый ProgramArguments[0] ДО того,
   как FDA-карточка может быть показана/кликнута — иначе клипборд скопирует старый .sh-путь.
   Механизм — существующий `refreshEngineIfBundledChanged` → installer (#1: триггер через
   `engineScriptNames` += новый бинарь); developer обязан проверить фактический порядок в
   main.swift и закрыть гонку.
4. **Quarantine:** точечный strip ТОЛЬКО с установленного helper ПОСЛЕ проверки SHA (Sol);
   не рекурсивный -cr. (#1-эксперименты уже показали: exec заквантиненного ad-hoc проходит —
   strip остаётся страховкой.)
5. **Сборка .app:** артефакт шипится в Resources; **байт-страж release-blocking** — SHA-256
   артефакта в repo == в собранном бандле ПОСЛЕ codesign (#1-эксперимент: --deep не трогает
   Resources; страж ловит регресс этого свойства).
6. **Тест «апдейт → грант жив» с negative control** (Sol): пересобранный helper с другим cdhash
   ОБЯЗАН потерять доступ — доказывает, что тест имеет зубы. Чистой VM нет — масштаб: локальная
   симуляция апдейта + negative control; Intel-слайс smoke через Rosetta (если доступен).
7. **Артефакт в git** (~50–100 КБ, публичный репо) — ДА, с PROVENANCE.md (наш код, GPL-линия
   не задета). Решение Юрки на вопрос #1.
8. **R1b (#1, принято):** человек выдаёт грант новому бинарю ОДИН РАЗ до релиза (боевой путь,
   проверка через тест-метку) → релиз v1.0.2 проходит для него без единого похода в настройки.
