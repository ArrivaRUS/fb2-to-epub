# План v1.0.2 «бинарный раннер» — Архитектор #1 (Claude)

> Вход: доказанный диагноз debugger (Tahoe 26.5.2 атрибутирует TCC-запрос launchd-агента
> к Mach-O образу процесса; subject=/bin/bash для shebang-скрипта; грант скрипту мёртв;
> грант приложению агента не покрывает; дочерние атрибутируются к responsible;
> чинить только ProgramArguments[0]). Дата: 2026-07-23.

## 0. Вердикт развилки: **A — standalone stable-bytes Mach-O helper**

### Почему A работает (TCC-механика)
Строка FDA для standalone CLI-бинаря, добавленного руками через «+»: `client` = абсолютный
путь (client_type=path), `csreq` = designated requirement бинаря НА МОМЕНТ выдачи. Для
ad-hoc подписи DR = `cdhash H"…"` — жёстко к байтам. Значит грант живёт, пока стабильны
ДВЕ оси: путь и байты. Обе — наши: путь фиксирован (`App Support/fb2-to-epub/bin/`),
байты заморожены (артефакт в git + cmp-preserve инсталлера; апдейты приложения файл не
трогают). Субъект запроса = Mach-O образ responsible-процесса → наш бинарь, НЕ /bin/bash
и НЕ platform binary → класс «Platform binary prompting is Deny» уходит. Промпта у FDA не
бывает в принципе (сервис только ручной) — карточка v1.0.1 остаётся единственным CJM и
переиспользуется без изменения механики.

### Почему не B (helper внутри бандла) — два независимых смертельных удара
1. **Даже без апдейта.** Существующая строка приложения хранит csreq = ad-hoc DR
   ГЛАВНОГО бинаря приложения (его cdhash). Хелпер в бандле — другой Mach-O с другим
   cdhash → валидация процесса агента по csreq строки не пройдёт. «Существующий грант
   покроет агента, нулевой UX» — иллюзия при ad-hoc: bundle-id — лишь ключ строки,
   валидация — по csreq.
2. **С апдейтом.** Авто-апдейт меняет главный бинарь → новый cdhash → даже свежевыданный
   грант молча умирает КАЖДЫЙ релиз — ровно паттерн, от которого уходим, в худшей форме
   (после каждого апдейта — снова в System Settings). B жизнеспособен только с Developer ID
   (DR по TeamID переживает версии). Его нет → B отклонён.

### Почему не C (SMAppService/BundleProgram)
Красивая атрибуция агента к приложению не лечит главное: грант приложению всё равно
пиннится ad-hoc-cdhash'ем → та же смерть на апдейте. При этом цена велика: статический
plist в бандле не умеет наших install-time значений (WATCH_DIR/env генерит инсталлер) →
перенос конфига в файл и слом контракта watcher; ломаются CLI install.sh, вся
launchctl-обвязка тестов, метка агента (миграция), добавляется Login Items UX.
Большой рефакторинг, ноль выигрыша по ключевой проблеме. Правильный трек ПОСЛЕ покупки
Developer ID (тогда пересмотреть C, и B становится безопасным) — зафиксировать как
будущее направление, не сейчас.

### Отклонённые экзотики
- Копия /bin/bash под нашим путём: платформенность определяется подписью, не путём →
  тот же Deny-класс; плюс чужой бинарь в дистрибутиве.
- Symlink на granted-путь: TCC резолвит realpath — субъектом станет цель ссылки.

## 1. Хелпер: поведение, сборка, хранение

**Имя/путь:** `~/Library/Application Support/fb2-to-epub/bin/fb2-to-epub-agent`.
НЕ «fb2-to-epub-runner»: в FDA-панели человека уже сидит ВКЛЮЧЁННАЯ мёртвая строка
`fb2-to-epub-runner.sh`; почти неотличимое имя рядом провоцирует «у меня уже включено».
Новое имя снимает двусмысленность шага 3 карточки. (Развилка для суда: имя.)

**Поведение (крошечный C, ~80 строк):**
- свой путь через `_NSGetExecutablePath` + realpath (не argv[0]); watcher — рядом;
- **posix_spawn `/bin/bash <watcher>` РЕБЁНКОМ и waitpid — НЕ exec.** Это ядро дизайна:
  субъект TCC = Mach-O образ responsible-процесса на момент запроса. exec заменил бы
  образ на /bin/bash → регресс ровно в текущий баг. Живой хелпер-родитель держит образ
  = гранту; дети (bash→python3→Calibre) атрибутируются к нему — доказано E1-логом.
- env наследуется как есть (WATCH_DIR/PATH/CALIBRE_MACOS_DIR/EBOOK_*/PYTHON3 из plist);
- SIGTERM/SIGINT/SIGHUP форвардятся ребёнку (trap'ы watcher отрабатывают, lock чистится),
  exit-код ребёнка пробрасывается; watcher отсутствует → stderr + ненулевой выход
  (паритет нынешнего runner.sh).

**Сборка и байт-стабильность:** исходник + one-shot скрипт в `packaging/agent-src/`
(clang -Os, arm64 + x86_64 → lipo universal, min macOS 11.0 = контракт приложения, strip,
ad-hoc codesign). Собирается ВРУЧНУЮ ОДИН РАЗ; артефакт `packaging/fb2-to-epub-agent`
(~50–100 КБ) коммитится в git и замораживается: build-app.sh его НИКОГДА не пересобирает.
Это сознательно НЕ «воспроизводимая сборка», а замороженный артефакт — единственная
железная гарантия байт-в-байт (дрейф toolchain/SDK не властен). Пересборка = редкое
осознанное событие: новый cdhash = у пользователей умирает грант → пометка в release
notes «нужен повторный доступ». Рядом `PROVENANCE.md`: исходник, точная команда, sha256,
cdhash, правило «не пересобирать». `.gitignore`-комментарий «binaries are not committed»
уточнить исключением.

**Проверено мной эмпирически на этой машине (scratchpad):**
- `codesign --force --deep -s -` по бандлу НЕ трогает Mach-O в Contents/Resources:
  sha256 до/после идентичен, strict verify OK → цепочка байт-стабильности
  git-артефакт → Resources → App Support/bin жива. Страж всё равно ставим (T4).
- Прямой exec заквантиненного ad-hoc бинаря на этой ОС прошёл (нюанс к риску №3 —
  строгость Gatekeeper зависит от контекста/провенанса; страховку оставляем).

## 3. Миграция установки человека
Вся цепочка — существующая, ни одного нового механизма:
авто-апдейт заменяет .app → первый запуск → `refreshEngineIfBundledChanged()`:
`fb2-to-epub-agent` отсутствует среди installed → differs → штатный `installer.sh`
(уроки 015/017/018 не задеты: боевой plist меняется ТОЛЬКО им; тест-оверрайды — под
защёлкой) → plist на новый бинарь + bootout/bootstrap → агент пробит папку:
- грант ещё не выдан → `denied` → карточка v1.0.1 сама всплывает (edge-pop), клипборд
  уже копирует НОВЫЙ путь (runnerPath() читает plist) → человек включает галку →
  «Проверить снова» → ok;
- грант уже выдан на R1b (см. T1) → агент зелёный сразу, карточка не появляется вовсе —
  это и есть живое «апдейт → грант жив».
Старые гранты (runner.sh, приложение) не чистим — инертны. Установленный runner.sh
удаляется инсталлером (файл наш); его TCC-строка остаётся видимой в панели — безвредно.

## 4. Тест-план (гейты)
- **T0 — R1a, validation-first, БЕЗ гранта (ГЕЙТ №1, до любой интеграции):**
  изолированный тест-агент (тест-метка под защёлкой 015, throwaway HOME/state — харнесс
  R1 из v1.0.1), ProgramArguments[0]=собранный хелпер, WATCH_DIR=throwaway-подпапка в
  защищённой зоне. Ожидание: (а) tccd-лог: AUTHREQ_SUBJECT = путь хелпера, НЕ /bin/bash;
  (б) `folder_access:"denied"` в тестовом state.json (цепочка хелпер→bash→python3 жива).
  Субъект неверный → СТОП, план пересматривается.
- **T1 — R1b, один ручной грант человека ДО релиза:** замороженный бинарь кладётся на
  боевой путь App Support/bin АДДИТИВНО (боевой plist/агент не трогаются — файла они не
  знают; исключение согласовать судом), тест-метка-агент указывает на него; человек
  выдаёт FDA один раз; probe → `ok` в тестовом state.json. Полный allow-путь доказан;
  грант остаётся и обслужит релиз.
- **T2 — поведение хелпера (без TCC, песочница):** watcher-маркер исполнился; exit-код
  пробрасывается; SIGTERM хелперу → ребёнок получил TERM (trap-маркер); нет watcher →
  ненулевой выход + stderr.
- **T3 — инсталлер:** ProgramArguments[0]=…/bin/fb2-to-epub-agent; бинарь исполняемый и
  БЕЗ com.apple.quarantine (источник в фикстуре предварительно заквантинен); runner.sh
  из bin/ удалён; повторный прогон НЕ переписывает бинарь (inode/mtime неизменны);
  негативы: без защёлки боевой plist байт-в-байт (lib-prod-guard / уроки 015/018).
- **T4 — байт-стабильность:** страж в build-app.sh (cmp git ↔ Resources после
  codesign --deep) + тест; update-install-цикл: после «апдейта» установленный бинарь
  байт-в-байт прежний и путь в plist прежний ⇒ инварианты выживания гранта (path+csreq).
- **T5 — строки/UI:** FDAShot-рендеры карточки с новым именем; grep-страж «runner.sh» по
  shipped-поверхностям (карточка/инсталлер/README), чтобы старое имя не всплывало.
- **T6 — полная регрессия** (fda-probe, юниты, install/update, обложки, fb3 — весь набор).
- **T7 — живой e2e на этой машине (боевой):** апдейт → refresh сам перевёл plist →
  бросить .fb2 в Desktop-папку → конвертация БЕЗ похода в System Settings (грант с T1
  уже жив) = живое «апдейт приложения → грант жив». Если T1 пропускали — грант выдаётся
  сейчас по карточке, затем повторная проверка апдейтом следующего патча.

## 6. Риски
1. **Пост-exec атрибуция** (главный) — закрыт дизайном (wait-модель, не exec) и
   T0-гейтом до всякой интеграции.
2. **codesign --deep переписал бы Resources-бинарь** — эмпирически опровергнуто здесь;
   страж T4 держит инвариант на других toolchain/ОС навсегда.
3. **Quarantine на хелпере** (SIGKILL Gatekeeper при exec из launchd) — вероятность
   средняя (контекст-зависимо; прямой exec у меня прошёл; launchd/syspolicyd-путь и
   реальная browser-провенанс не проверены) → дешёвая страховка: xattr-strip в
   инсталлере + ассерт в T3. Авто-апдейт и так стрипает quarantine с .app.
4. **Случайная пересборка артефакта** («обновили» бинарь) → новый cdhash → грант молча
   умирает у всех. Митигция: PROVENANCE.md + T4-страж + правило в README агент-src.
5. **Intel-слайс живьём не проверить** (машина arm64): smoke `arch -x86_64` при
   наличии Rosetta; риск низкий (тот же clang).
6. **Три строки в панели FDA** (runner.sh ON-мёртвая, app ON-инертная, agent новая) —
   карточка называет точное новое имя; отличимость — причина переименования.
7. **Будущие ужесточения Apple** (нотарификация для FDA-целей и т.п.) — вне контроля;
   стратегический выход — Developer ID, тогда пересмотреть C/B.
8. **Бинарь в публичном репо** — supply-chain-оптика; закрыто провенансом (исходник +
   команда + sha256 + cdhash рядом с артефактом).

Примечание вне скоупа (для беклога): `engineScriptNames` не содержит fb3-файлов —
fb3-only изменение движка не триггерит refresh на апдейте. Существующая латентная щель,
не связана с фичей.
