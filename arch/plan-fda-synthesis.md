## Вердикт
Каркас — **#1 (Claude)**: контракт `agent.folder_access` (флэт, 2 ключа), тристейт
`ok|denied|missing`, kickstart **БЕЗ -k**, авто-поднятие приложения на переходе →denied,
validation-first R1, FolderAccessCard в 4 подачах. Влиты находки **#2 (Codex)** — список ниже.

## Взято из #1 (Claude) — каркас
- **Контракт (D13, аддитивно, schema=1):** `agent.folder_access: "ok"|"denied"|"missing"` +
  `agent.folder_access_ts` (ISO-8601 UTC), флэт — тот же атомарный RMW-паттерн, что batch_state.
  errno — в ЛОГ, не в state (контракт минимальный). Отсутствие поля = unknown → ноль подач.
- **Проба:** python `os.listdir(WATCH_DIR)` на КАЖДОМ запуске watcher'а; PermissionError
  (EPERM∪EACCES) → denied (слияние делает chmod-симуляцию в тестах эквивалентной боевому TCC);
  ENOENT/ENOTDIR → missing; прочие OSError → missing + errno в лог. Пустая папка = ok.
- **kickstart БЕЗ `-k`:** агент короткоживущий; `-k` убил бы живую конвертацию ради recheck.
- **Авто-поднятие окна на переходе →denied** (`open -b`, паттерн new-batch, ровно 1 раз на
  переход — edge-pop в состоянии агента): пользователь узнаёт о поломке, не открывая окно.
  Это «активное действие» из заказа D46.
- **R1 validation-first:** ПЕРВЫЙ шаг разработки — изолированный тест-агент (тест-метка,
  throwaway) с WATCH_DIR = защищённая зона → предъявить `"folder_access":"denied"` в тестовом
  state.json ДО постройки UI (допущение «listdir под launchd без FDA даёт PermissionError»
  подтверждено пока только косвенно боевым логом).
- **FolderAccessCard** — НОВЫЙ компонент по грамматике/токенам EngineSetupCard (в сам
  EngineSetupCard не встраивать — связывать автоматы свежей v1.0.0 нельзя); 4 подачи
  (блокер/баннер по гибриду D37 · шаг Setup · строка Настроек) × автомат
  denied/checking/stillDenied/timeout. `FB2_FORCE_FOLDER_ACCESS` — display-only зеркало.
- **missing** есть в контракте, но БЕЗ UI в v1.0.1 (лог + отсутствие FDA-подачи; скоуп D46).

## Взято из #2 (Codex) — находки и защёлки
- **`mkdir -p` на старте watcher'а НЕ должен создавать WATCH_DIR** (watcher.sh:99 — проверено):
  иначе удалённая папка автовоссоздаётся и missing недостижим. Создание папки — зона installer.
- **Позиция пробы:** после lock, ДО Calibre-чека/count_pending/find (probe-and-publish даже
  когда конвертаций нет — иначе под TCC-блоком state.json не обновился бы никогда).
- **Recheck-семантика:** запомнить `folder_access_ts` до kickstart; результат принимать ТОЛЬКО
  при ИЗМЕНИВШЕМСЯ ts (событийно через существующий stateWatcher, debounce 150мс; fallback-поллинг
  250мс только на время операции; таймаут 8с с учётом ThrottleInterval=5). Таймаут/ошибка
  launchctl = отдельное состояние «Агент не ответил», НЕ повторный denied.
- **Честные тексты:** errno не доказывает именно TCC → заголовок «Нет доступа к папке»
  (не «нужен Full Disk Access» как утверждение); инструкция ведёт к FDA как самой вероятной причине.
- **Deep-link fallback:** `Privacy_AllFiles` — нестабильный API → при неудаче открывать корень
  «Конфиденциальность и безопасность».
- **Клипборд:** путь = `ProgramArguments[0]` из УСТАНОВЛЕННОГО plist (plutil), фолбэк — вычисленный
  от home; сначала NSPasteboard, потом панель. Runner в фиче не менять ни байтом (грант «по байтам»).
- **Тест-изоляция:** отдельный **`FB2_LOCK_DIR`** (env-дефолт в watcher) — иначе тесты пересекаются
  с боевым `/tmp/fb2-to-epub.lock.d`; chmod-симуляция на РОДИТЕЛЕ + trap-восстановление; снапшот-страж
  боевых артефактов (урок 018).

## Развилка, решённая судьёй
**Приоритет подач при «нет движка И нет доступа»:** Codex — сначала FDA; Claude — сначала движок.
**Решение: порядок CJM — движок → доступ** (активная установка движка → нет движка → denied →
обычный Status). Онбординг v1.0.0 уже ведёт за руку от движка; после success двиг-подача уходит
и FDA-шаг всплывает сам. Уже начатую установку FDA-карточка не перебивает (совпадение обоих планов).

## Отброшено (с причиной)
- `kickstart -k` (Codex) — риск убить живую конвертацию.
- Объект `watch_dir_access{status,errno,checked_at}` (Codex) — флэт из 2 ключей проще и достаточен.
- Sentinel-файл, probe-файл, детект приложением, расширение EngineSetupCard, поллинг постоянный,
  запись только-по-изменению — отвергнуты обоими/судьёй (обоснования в исходных планах).
