# 007 — Очередь обложек показывала удалённые книги (нет валидации существования)

**Дата:** 2026-06-26 · **Фаза:** после релиза (человек тестирует v0.2.x)

## Что сломалось
Человек удалил отслеживаемую папку (исходники + сконвертированные epub). Раздел **«Выбрать обложку»** всё равно открывался и показывал обложки книг, которых уже нет — применить/поменять нечего (epub удалён).

## Почему (настоящая причина)
Очередь обложек (`covers/queue/<id>.json`) — persistent-записи, ссылающиеся на epub по полю `epub_path`. `CoverQueueStore.loadPending()`/`pendingCount()` отдавали ВСЕ pending-записи, **не проверяя, существует ли целевой epub**. А действие (выбор обложки → вшить агентом в epub) бессмысленно, если epub удалён. Очередь жила своей жизнью, оторванной от реальности на диске.

## Как починили
`loadPending()` фильтрует записи по `FileManager.default.fileExists(atPath: epub_path)` (+ `status == pending`). → удалённые книги не в очереди; `coverQueueCount()` = 0 → строка «Выбрать обложку» в Статусе гаснет; вход в раздел уводит на Статус (`guard let first = queue.first`). Самоочистка: мёртвые `queue/<id>.json` (epub отсутствует) удаляются при загрузке. Страховка на «Применить»: повторная проверка epub, исчез → алерт «Книга больше не найдена» + убрать из пейджера. Коммит `47af94f`. **Проверено вживую:** все 10 epub удалены → бейджа нет, форс-вход уводит на Статус, очередь самоочистилась (10→1).

## ПРАВИЛО НА БУДУЩЕЕ
Persistent-очередь/список, ссылающийся на внешние файлы (epub, документы, пути) — на входе ВАЛИДИРОВАТЬ существование цели и не предлагать действие, если объекта уже нет. Файлы пользователя живут своей жизнью (он их удаляет/двигает) — UI обязан отражать реальность на диске, а не устаревший снимок. Распространить принцип на любые будущие «очереди задач по файлам».
