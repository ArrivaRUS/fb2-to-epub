# 016 — «Continue-on-failure» опубликовал битую work-копию; стаб-тесты этого НЕ ловили

**Дата:** 2026-07-01 · **Фаза:** v0.9.7 (правка метаданных EPUB), код-ревью до релиза

## Что нашли (код-ревью, до отгрузки)
Новый confirm-путь `apply_meta_only_into_epub` (watcher): `cp epub → work; ebook-meta work …; mv -f work epub`.
`mv` стоял БЕЗУСЛОВНО — даже когда `ebook-meta` вернул non-zero. Политика была «meta-fail → всё
равно resolved (не мозолить из-за редкого сбоя метаданных)», НО реализована неверно: при сбое
`ebook-meta` **посреди** in-place правки (Calibre распаковал → правит OPF → крашнул на перепаковке)
`work` оказывается БИТЫМ, и `mv` **затирает хороший оригинал битой копией**. Т.е. «continue on
failure» превратилось в «опубликуй повреждённый результат». Cover-путь этой дырой НЕ страдал — там
polish пишет в отдельный `final_tmp`, `mv` только при успехе+непустоте.

## Почему стаб-тесты (44/44 зелёные) это пропустили
Стаб `ebook-meta` в изолированном тесте выходил с non-zero **не трогая файл** — покрыт только
«clean fail». Реального сценария «бинарь испортил файл И упал» стаб не воспроизводил, а именно он
и опасен. Зелёный набор давал ложную уверенность.

## Как починили
- Watcher: при `meta_rc != 0` → `rm -f work` + `return 2`, БЕЗ `mv` (оригинал байт-в-байт цел);
  карточка всё равно резолвится по политике (вызывающий не меняли). При `meta_rc == 0` — прежний `mv`.
- Заодно M2: `mktemp` создаёт work/tmp РЯДОМ с целевым epub (`dirname`) → `mv` гарантированно
  same-volume rename (атомарно), а не copy+unlink через `$TMPDIR` на другом томе. Починило и старый
  `polish_cover_into_epub`.
- Новый тест: стаб `ebook-meta`, который ПОРТИТ work + возвращает non-zero → assert `sha256` EPUB
  до/после **идентичен** (битую копию не опубликовали).
- **Живой e2e с настоящим Calibre** (зона Юрки): реальный `ebook-meta --title= --authors=` на
  настоящем EPUB → метаданные реально переписаны; `ebook-polish --cover` поверх → сохранены + обложка вшита.

## ПРАВИЛО НА БУДУЩЕЕ
- **«Continue on failure» ≠ «опубликуй частичный результат».** Если шаг мутирует файл на месте и
  может упасть посреди — работай на temp-копии и заменяй оригинал (`mv`) ТОЛЬКО при полном успехе
  шага. При сбое — удали temp, оригинал не трогай (даже если по политике «идём дальше»).
- **Стабы дают ложную уверенность про внешние бинари.** Стаб-тесты проверяют КОНТРАКТ (argv, порядок,
  инъекция, атомарность логики), но НЕ реальное поведение Calibre/ffmpeg/любого внешнего инструмента.
  Перед релизом интеграции, которая шеллит во внешний бинарь, — ОБЯЗАТЕЛЕН ≥1 живой e2e на настоящем
  инструменте в изолированной temp-среде (создать реальный вход → прогнать реальную операцию →
  прочитать результат обратно). Усиливает [[test-override-never-on-production-path]] (verify — только
  изолированные temp-пути, боевой агент/plist/папку не трогать).
- Стаб «чистого сбоя» — недостаточно: добавляй стаб «сбой С порчей входа», чтобы поймать publish-on-fail.
