# Урок 003 — ширина DMG-окна на macOS 26 + гонка codesign в iCloud-папке

**Когда:** 2026-06-24 (после отгрузки v0.1.0; пользователь скачал релизный `.dmg` и увидел белый провал справа + кривую стрелку).

## Что случилось
1. **Белый провал справа.** macOS 26 (Tahoe) **игнорирует размер окна из `.DS_Store`** и
   открывает DMG-окно **~920×436** (контент ~920×408). Фон был 660×400 → справа ~260px
   белого провала, контент прижат влево. У меня на машине провала не было — Finder
   «запоминал» геометрию тома `fb2-to-epub` по прошлым тест-монтированиям (660), а у
   пользователя свежая система → окно 920. Я проверял на закэшированном окне и не увидел
   того, что видит пользователь.
2. **Стрелка в шапке** «fb2 ❯ epub» не была отцентрована между словами.
3. **Битая подпись при пересборке.** Репо лежит в `~/Documents` (iCloud/fileprovider).
   Демон **асинхронно** проставляет `com.apple.FinderInfo` на корень бандла **между**
   `xattr -cr` и `codesign`. `codesign --force --deep` падает с «resource fork, Finder
   information, or similar detritus not allowed», а с `set -euo pipefail` весь
   `build-app.sh` умирает, оставляя `.app` с невалидной подписью (`invalid Info.plist`).

## Правило на будущее
- **Фон DMG ≥ окна, контент по центру.** Под macOS 26 фон рисуем **960×440** (шире/выше
  окна 920×408), тёмным до всех краёв; контент центрируем под видимые 920 (центр x=460,
  слоты иконок 290/630). Меньше окна = белый провал у конечных пользователей.
- **Проверять рендер на УНИКАЛЬНОМ имени тома.** `make-dmg.sh … --test` (volname
  `fb2-to-epub-test-<ts>`) → Finder не подставит закэшированную геометрию → видишь
  СВЕЖИЙ рендер = то, что увидит пользователь. Закрыть все окна Finder + перемонтировать,
  иначе том откроется вкладкой в чужом окне (чужая боковая панель/тулбар в кадре).
- **`-D` флаги make-dmg передают только пути.** Геометрия (окно, позиции иконок) — в
  `dmg-settings.py`. Строки `echo`/комментарии в `make-dmg.sh` — НЕ источник правды;
  держать их синхронными, чтобы не путали.
- **codesign в синхронизируемой папке — через ретрай-цикл.** «очистка xattr → codesign →
  дочистка FinderInfo → verify» в цикле (до 5 попыток), codesign под `if` (не под `set -e`).
  Это долговременный фикс `build-app.sh` (вынесено в отдельную задачу).
- **`FinderInfo` в `.app` внутри dmg — безвреден.** Его проставляет сам dmgbuild при
  упаковке (бит «кастомная иконка»). Приложение проходит `codesign --verify --deep`
  (подпись валидна, Gatekeeper запускает) и падает только на `--deep --strict`.
  Проверено: оригинальный рабочий релиз `223ed2ac` вёл себя так же. Сборка из `/tmp`-копии
  НЕ помогает (dmgbuild всё равно ставит бит) и не нужна. Критерий годности — `--deep` (без `--strict`).
- **Релизный ассет обновляется вручную.** Локальные правки после релиза НЕ меняют файл в
  Release. После любого пост-релизного фикса: `gh release upload <tag> <file> --clobber`
  **и сверить скачиванием обратно** (sha). «Это точно последняя версия?» — корень был в
  том, что ассет не переобновили под исправленный фон.

## Добавление (2-я итерация по жалобе на ту же страницу)
Пользователь скачал исправленный образ и нашёл ещё два дефекта — оба РЕАЛЬНЫЕ:
- **Стрелка-перетаскивания «прижата вправо».** Корень: `cairosvg` **роняет тонкий
  stroke под фильтром** `feGaussianBlur+feMerge` (glow-arrow) — рендерился только
  «наконечник», тонкий «хвост» исчезал → видимый центр стрелки 536 вместо 460. Замер
  через PIL подтвердил (оранжевые пиксели только x=523..550). **Фикс: стрелка =
  СПЛОШНАЯ заливная фигура без фильтра** → cairosvg рисует надёжно, центр 459.
  Правило: для cairosvg НЕ полагайся на `feMerge`-фильтры для тонких штрихов; критичную
  графику делай заливкой и **проверяй PIL-замером** (центр/охват пикселей), а не на глаз.
- **Плашки «высокие, текст у нижнего края».** Finder рисует подпись иконки НИЖЕ, чем
  кажется: при иконке center y=190 + size 120 подпись центрируется на **y≈270**
  (icon_bottom 250 + ~20), а не на 262. Плашку надо центрировать на 270. Фикс: высота
  30→24, плашка 258..282 (центр 270). Проверено PIL-замером в реальном рендере:
  текст центрирован (над 11 / под 14px). Правило: позицию плашки под текст Finder
  выставляй по факту (PIL: диапазон бежевых vs тёмных пикселей), не по догадке.

Мета-урок: даже «очевидно симметричный» SVG может рендериться иначе (cairosvg-фильтры,
позиция текста Finder). Замеряй ПИКСЕЛИ итогового PNG/скрина (PIL), это быстрее и
честнее, чем глаз. Эти две итерации Юрка делал прямыми правками SVG+render+PIL-проверкой
(tight loop, который может верифицировать только он) — см. anti-drift в HEARTBEAT.
