# 008 — «Искать ещё» не искал бы по EPUB: Calibre синтезирует обложку → has_embedded_cover==True

**Дата:** 2026-06-26 · **Фаза:** разработка v0.2.7 (переиск обложек)

## Что сломалось
Фича «Искать ещё» (переиск новых обложек вместо показанных) на уже-сконвертированном EPUB ничего бы не находила: finder в research-режиме берёт epub как источник меты, а Calibre `ebook-meta --get-cover` для EPUB **синтезирует** «обложку» из первой страницы (~40 КБ > `MIN_BYTES`) → `has_embedded_cover()` == True → finder выходит кодом 3 («обложка уже есть, поиск не нужен») → очередь не обновлялась.

## Почему (настоящая причина)
Проверка `has_embedded_cover` правильна для ПЕРВИЧНОЙ конвертации (есть вшитая обложка — не искать). Но «Искать ещё» — явный запрос пользователя на АЛЬТЕРНАТИВЫ, когда обложка уже есть (авто-подобранная или синтезированная) и именно она не устраивает. Гейт «уже есть → не искать» противоречит смыслу действия.

## Как починили
В `cover-finder.py run_json`: `refresh = bool(exclude)` поднят выше проверки обложки; сама проверка гейтится `if not refresh and has_embedded_cover(src): sys.exit(3)`. В research-режиме (передан `--exclude`) embedded-cover игнорируется — finder всегда идёт в онлайн-поиск. Первичный поиск (без `--exclude`) не изменён. Проверено: один и тот же epub с вшитой обложкой → без `--exclude` exit 3, с `--exclude` ищет и возвращает кандидатов; в e2e-прогоне watcher'а (Война и мир) research переписал очередь, несмотря на Calibre-обложку.

## ПРАВИЛО НА БУДУЩЕЕ
Действие вида «найди альтернативы / поищи ещё / перегенерируй» НЕ должно гейтиться условием «у объекта уже что-то есть» — пользователь просит замену именно потому, что текущее не подходит. Короткозамыкатели («уже есть → пропустить»), уместные в авто-пайплайне, надо ОТКЛЮЧАТЬ на путях явного пользовательского переиска/регенерации. Распространить на любые «regenerate/refresh» фичи.
