# 019 — Живое окно тест-сборки на боевой машине невозможно: тот же bundle-id + свой агент

**Дата:** 2026-07-22 · **Фича:** FDA-онбординг (v1.0.1) · **Нашёл:** Юрка на live-verify

## Что случилось
Хотел прокликать FDA-карточку в НАСТОЯЩЕМ окне (правило «рендер ≠ интеракция»). Три попытки
поднять тест-сборку с засеянным `folder_access:denied` — все провалились по РАЗНЫМ причинам,
складывающимся в один вывод: **живое окно тест-билда на машине с установленным боевым
приложением недостижимо.**
1. Тест-приложение при первом запуске делает first-run setup → ставит throwaway-агента, тот
   пробит throwaway-Desktop (нет папки) → пишет `missing` ПОВЕРХ засеянного `denied` → карточки нет
   (у `missing` нет UI по замыслу). Лечится `FB2_SKIP_KICKSTART=1` + миграционной веткой (плист есть).
2. Но даже с выжившим `denied`: у тест-сборки ТОТ ЖЕ `CFBundleIdentifier` (`com.arrivarus.fb2toepub`),
   что у боевого приложения из /Applications. Два процесса с одним bundle-id → скриншот/фронт ловит
   БОЕВОЙ инстанс (версия 1.0.0 в футере), тестовое окно 1.0.1 прячется. `open_application` по
   bundle-id неоднозначен.

## Почему офскрин-рендер — правильный выбор (его сделал developer)
Офскрин-харнесс (`tests/FDAShot`) рендерит подачи в PNG без запуска боевого lifecycle: не трогает
engine/agent/home, не конфликтует по bundle-id, детерминирован. Для ПИКСЕЛЕЙ это исчерпывающе.

## Что тогда покрывает интеракцию
- Логика recheck/dissolve/ts-семантики — Swift-юниты с инжектом часов (reviewer-verified).
- Проба→denied на реальном launchd — R1-валидация (тест-метка, throwaway) прошла на этой машине.
- Кнопка (clipboard+панель) и edge-pop (авто-поднятие окна) — единственные НЕ покрытые живьём;
  их подлинная проверка = боевой denied-стенд ПОСЛЕ релиза (реальный TCC + реальный грант юзера,
  который всё равно user-only-действие). Это не «ship на стабах»: рантайм-звенья покрыты, живым
  остаётся только клик, невоспроизводимый в изоляции из-за bundle-id.

## Правило на будущее
1. **Для живого окна нативного приложения на машине с установленным боевым — меняй bundle-id
   тест-сборки** (напр. суффикс `.dev` в build-app.sh при dev-версии), иначе фронт/скриншот ловит
   боевой инстанс. Либо (проще) — офскрин-рендер + юниты + принять клик-проверку на боевом стенде.
2. Тест-стенд с засеянным state.json бесполезен, если приложение поднимает свой пробящий агент:
   либо `FB2_SKIP_KICKSTART=1`+миграционная ветка, либо делай папку реально denied (chmod 000),
   чтобы РЕАЛЬНЫЙ агент сам записал denied (не подделка).
3. После КАЖДОЙ возни с тест-агентом — bootout тест-метки + снапшот-страж боевых (плист/state/
   агент). Здесь: боевой denied-стенд сохранён байт-в-байт (state.json так и не создан).
